# NORMIA Visual Upgrade Plan V1.1

## Objective
Create a grounded visual upgrade for NORMIA that strengthens clarity, construction credibility, trust, and product communication across the homepage, platform page, field worker page, resources page, and contact page.

## Prioritized Changes by Impact

1. Hero redesign and page hierarchy
2. Trust-building and credibility structure
3. Strong product-focused CTAs
4. Value chain visualization and process clarity
5. Field Worker UX and mockup guidance
6. Mobile-first layout and interaction improvements
7. Typography and color system recommendations

---

## 1. Hero Redesign

### Goals
- Communicate what NORMIA is in one clear sentence
- Show who it is for and what value it delivers
- Establish credibility with a practical, construction-focused tone
- Encourage a low-friction next step

### Recommended approach
- Use a two-line heading with a strong product statement and a supporting subhead.
- Avoid vague phrases and marketing buzz; use concrete language like “Capture site progress, quality control and FDV evidence from the work itself.”
- Include a short supporting list or phrase beneath the headline:
  - “Task execution, photo control and FDV-ready delivery in one site workflow.”
- Add a visual anchor or mockup callout area that references the Field Worker experience.
- Use a bold primary CTA and a secondary calm action.

### Hero content structure
- Headline: “Documentation that grows from the work, not from reports.”
- Subhead: “NORMIA connects field tasks, photo evidence and quality control so projects stay aligned from execution to FDV.”
- Primary CTA: “Review the Field Worker flow” or “See the platform in practice”
- Secondary CTA: “Read the NORMIA value chain” or “Download methodology”

---

## 2. Visual Hierarchy and Page Structure

### Homepage
- Lead with the hero and immediately state the product’s role in construction workflows.
- Follow with a simple grid of three impact statements: “Fewer handoffs”, “Photo-based control”, “FDV-ready delivery”.
- Use section headings like “How NORMIA works”, “Who uses it”, and “What it delivers”.
- Keep navigation focused on the platform, resources, and contact actions.

### Platform page
- Open with a concise platform overview and a stronger emphasis on operational value.
- Use clear segment cards for each module: Field Worker, Knowledge Engine, Supervisor.
- Add a dedicated “Value chain” section with a visual progression.
- Close with trust signals and a direct contact CTA.

### Field Worker page
- Move beyond the list view to a layout that feels like a product walkthrough.
- Start with a practical problem statement: “Site teams need a single workflow for task execution, documentation and control.”
- Use a visual or mockup recommendation area to show the mobile-first task/photo process.
- Keep feature descriptions grounded in field execution terms.

### Resources page
- Position this as a library for construction and delivery practice, not as marketing collateral.
- Separate resources by type: system logic, methodology, examples, revisions.
- Use trusted document cues: “Project reference”, “Methodology brief”, “Revision history”.
- Add a short note on how the resources support project delivery and handoff.

### Contact page
- Keep the contact experience strong and simple.
- Lead with a clear use case: “Tell us about your project and we’ll show how NORMIA reduces manual reporting.”
- Use a button-style email link and a short bullet list of ideal project criteria.

---

## 3. Value Chain Visualization

### Why it matters
A construction audience needs to see how NORMIA fits into real delivery stages and how effort flows through the system.

### Recommended visualization
- Use a horizontal or stepped flow with discrete blocks:
  1. Plan task
  2. Execute work
  3. Capture photo
  4. Perform control
  5. Generate documentation
  6. Deliver FDV
- Label each block with a brief construction-friendly phrase.
- Use subtle iconography or simple shading to show reuse and continuity.

### Placement
- Place on the homepage and platform page right after the hero or overview.
- On the platform page, connect the flow to module responsibilities: Field Worker = execute and capture, Knowledge Engine = register and validate, Supervisor = control and verify.

## 4. Field Worker Mockup Recommendations

### Objectives
- Make the Field Worker page feel like a real site tool.
- Show the flow of tasks, photos and deviations clearly.

### Mockup guidance
- Suggest a mobile-first screen layout rather than a text-only list.
- Include the following content blocks:
  - Task list with progress indicators
  - Photo attachment card tied to a task or control point
  - Deviation report summary with status and next action
- Use real construction terminology: “Oppgave”, “Kontrollpunkt”, “Bilde”, “Avvik”.
- Show a clear handoff to documentation: “Once completed, the evidence is attached and ready for FDV.”

### Page layout ideas
- Lead with a visual mockup and a short summary sentence.
- Follow with three feature pillars: “Task execution”, “Field evidence”, “Documented delivery”.
- Add a testimonial-style quote or pilot note if available.

## 5. Typography Recommendations

### Goals
- Improve reading speed and hierarchy
- Make page sections scannable and credible
- Use neutral, modern type with good legibility

### Suggested system
- Headings: bold sans-serif with strong contrast and clear scale.
- Body: 16–18px base size with 1.5 line height.
- Section headings: 28–32px on desktop, 22–26px on mobile.
- Use a consistent weight system: bold for headings, medium for subheads, regular for body.

### Practical guidance
- Increase heading spacing and reduce line length in content sections.
- Keep paragraph blocks short and use bullets for feature lists.
- Use distinctive styling for cards and section headers to separate content visually.

---

## 6. Color Recommendations

### Goals
- Create a sober, credible palette for construction and operations
- Avoid loud startup palettes and overly “digital” gradients
- Use color to reinforce hierarchy and trust

### Suggested palette
- Primary: deep neutral / dark slate for headlines and actions
- Accent: calm construction blue or steel blue for links and subtle highlights
- Support: warm grey for backgrounds, stone grey for borders, soft black for text
- Status: muted green for success cues, amber for attention, neutral red for exceptions only

### Implementation
- Use a mostly white/neutral canvas with dark primary text.
- Reserve accent blue for interactive elements and small information highlights.
- Use block backgrounds sparingly to separate sections without feeling decorative.
- Keep the page grounded and functional, not flashy.

---

## 7. CTA Recommendations

### Principles
- Make CTAs concrete and action-oriented.
- Use product-focused phrasing rather than abstract marketing language.
- Prefer actions that invite review, demonstration or project conversation.

### Example CTA labels
- Primary: “See the Field Worker flow”, “Review the platform value chain”, “Talk project delivery”
- Secondary: “Read the methodology”, “Explore use cases”, “Download the process brief”

### Placement and styling
- Use a strong visible primary CTA in the hero.
- Add contextual CTAs after product descriptions and the value chain.
- Use simple button styling with high contrast and enough space around it.

---

## 8. Trust-Building Sections

### Recommended content blocks
- “Why NORMIA?” with 3 concise operational benefits
- “How it fits construction delivery” with use-case bullets
- “Built for site teams and handovers” or “Designed for execution, control and FDV”
- A small “How we work” block describing pilot projects or project types

### Trust signals
- Use concrete phrases like “Site-based documentation” and “FDV-ready delivery”.
- Avoid generic calls to action like “disrupt” or “scale”.
- Prefer functional credibility over flashy reassurance.

### Page placement
- Homepage: after the value chain and product module overview.
- Platform page: inside the module section and near the contact CTA.
- Contact page: include project suitability bullets and a clear business email.

---

## 9. Mobile-first Improvements

### Focus areas
- Ensure the hero and CTA are compact and readable on narrow screens.
- Collapse navigation into a simple stack at the top.
- Use full-width cards with generous vertical spacing.
- Convert horizontal flows into vertical progress steps on mobile.

### Specific recommendations
- Reduce hero line length and increase tap targets for CTAs.
- Stack module cards with consistent spacing and clear labels.
- Make the Field Worker mockup feel like a mobile screen, not a desktop summary.
- Keep contact details and email button easily reachable.

---

## Page-level highlights

### Homepage
- Introduce NORMIA with a stronger hero and a product-first statement.
- Add a compact value chain visual and three trust-oriented benefit cards.
- Make the navigation simpler and the first CTA more specific.

### Platform page
- Improve the module section with clear responsibilities.
- Add a value chain or workflow diagram directly tied to the module roles.
- Reinforce the platform’s operational purpose rather than high-level claims.

### Field Worker page
- Turn the page into a mobile-first product story.
- Show how tasks, photos and deviations move from execution to documentation.
- Recommend a mockup area and clearer feature structure.

### Resources page
- Position the page as a practical document library for project delivery.
- Use clearer labels for each resource type and highlight the benefit of each link.

### Contact page
- Keep the ask direct: project conversations, pilots, and construction delivery.
- Use the CTA button prominently and keep the email address visible.
- Add a small note on ideal project type to guide inquiries.

---

## Closing guidance

This V1.1 visual upgrade should be grounded, practical and oriented toward construction teams. The goal is to make NORMIA feel like a usable platform with clear product intent, not an abstract marketing concept.

Focus on structure, clarity, and credibility first. Use visual hierarchy, restrained color, concrete language, and mobile-ready layouts to support the product story on every page.
